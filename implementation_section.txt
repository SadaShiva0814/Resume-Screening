### 6.1 Project Modules and Algorithm

The AI-powered Resume Screening System is architected into several specialized modules that handle the end-to-end pipeline from raw document ingestion to semantic ranking.

#### Key Modules:
1. Data Extraction Module (extractor.py): Responsible for parsing multi-format documents (PDF, DOCX). it preserves structural integrity to ensure data is correctly categorized.
2. Section Parsing Module (section_parser.py): Uses a heuristic-based engine to segment resumes into logical blocks such as Work History, Skills, Education, and Projects.
3. Semantic Scoring Engine (semantic_scorer.py): The "Brain" of the system. It uses Signal Isolation (Max Paragraph Similarity) to identify high-density matching areas within a section while ignoring irrelevant "noise."
4. Vector Search Module (FAISS): Implements an ultra-fast indexing system allowing for sub-millisecond similarity searches across large candidate pools.
5. Feedback Learner (feedback_learner.py): A reinforcement layer that refines the matching logic based on user interactions (Top/Bottom ranking adjustments).
6. Evaluation Metrics Engine (evaluator.py): Computes analytical metrics like Spearman Rank Correlation and Score Distribution Entropy to validate ranking quality.

#### Core Algorithms:
* SBERT (Sentence-BERT): Generates 384-dimensional semantic embeddings to capture the context of sentences rather than just keywords.
* Cosine Similarity: Used to measure the angular distance between Job Description vectors and Resume Section vectors.
* Signal Isolation: A custom algorithm that splits sections into paragraphs and selects the maximum match strength, preventing long resumes from diluting high-quality specific matches.
* Ontology-based Skill Matching: Standardizes variation in terminology (e.g., "JS" vs "JavaScript") using a predefined skill graph.

### 6.2 Introduction to Testing

Testing in this AI-centric project goes beyond traditional software verification. Since the system relies on unsupervised learning (embeddings), testing focuses on Ranking Robustness and Semantic Accuracy.

The testing strategy is divided into three tiers:
1. Functional Testing: Ensures that file uploads are successful, metadata is correctly stored in MongoDB, and the UI responds correctly to user filters.
2. Algorithm Validation (Evaluation Metrics): Uses proxy metrics to measure how well the AI differentiates between "good" and "bad" candidates.
    * Discriminative Power: Measured via Score Entropy to ensure the system isn't assigning the same score to everyone.
    * Rank Stability: Ensuring that minor edits to a resume don't cause wild swings in its rank.
3. Semantic vs. Keyword Baseline: The system is tested against a traditional TF-IDF keyword matcher. Success is defined by the system's ability to rank a candidate high who uses synonyms or contextually similar terms that keyword matchers would miss.

### 6.3 Software Testing Life Cycle (STLC)

The project follows a rigorous STLC to ensure the reliability of the screening results:

1. Requirement Analysis: Identifying technical requirements (supported file types, matching speed targets) and AI performance goals (accuracy of skill extraction).
2. Test Planning: Defining the "Evaluation Proxy" strategy since no ground-truth labels exist. Planning for "Ablation Studies" to test how each section weight affects the final rank.
3. Test Case Development:
    * Unit Tests: For parsers, extractors, and embedding functions.
    * Edge Case Tests: Handling corrupted PDFs, empty resumes, and extremely long job descriptions.
    * Bias Testing: Ensuring the algorithm doesn't favor specific formatting styles.
4. Environment Setup: Configuring the local MongoDB instance and vector indexes to mirror the production Hugging Face environment.
5. Test Execution:
    * Regression Testing: After updating the SBERT model, re-ranking old sessions to ensure quality hasn't dropped.
    * User Acceptance Testing (UAT): Manual review by HR personas to verify if the "Top 5" matches align with human expectations.
6. Test Cycle Closure: Final analysis of the Spearman Rank Correlation to prove the system's value over traditional ATS tools.
